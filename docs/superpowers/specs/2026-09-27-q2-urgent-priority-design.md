# D题第二问急送优先模型设计

## 1. 目标

将第二问评价逻辑从“全部物资越早越好”调整为：

1. 全部80箱必须按各自截止时间送达；
2. 在全箱按时的前提下，优先改善急送物资的送达及时性；
3. 随后依次降低总飞行能耗、架次数和完工时间；
4. 正式实验只比较受限一体化 CP-SAT 与 Hybrid 两个顶层算法。

## 2. 物资分类与截止时间

急送物资集合定义为

\[
B^{\mathrm{urgent}}
=\{b:b\text{ 为首批保障物资或医疗物资}\}.
\]

当前数据中急送物资31箱，普通物资49箱。

对急送物资，强制截止时间沿用现有规则：首批保障截止时间和医疗物资期望时间同时存在时取较早值。对普通物资，将期望送达时间作为强制截止时间。由此每个物资箱都有强制截止时间 \(\bar\tau_b\)，并满足

\[
T_b^{\mathrm{delivery}}\le\bar\tau_b,
\qquad \forall b\in B.
\]

## 3. 正式目标

急送物资加权归一化送达时间定义为

\[
Z_{\mathrm{urgent}}
=\frac{
\sum_{b\in B^{\mathrm{urgent}}}
w_bT_b^{\mathrm{delivery}}/\tau_b^{\mathrm{exp}}
}{
\sum_{b\in B^{\mathrm{urgent}}}w_b
}.
\]

在全部硬约束满足后，正式目标采用严格词典序：

\[
\min_{\mathrm{lex}}
(Z_{\mathrm{urgent}},E,K,M),
\]

其中 \(E\) 为总飞行能耗，\(K\) 为架次数，\(M\) 为最后一架无人机返航时刻。

搜索过程中允许暂时存在迟到候选，内部质量向量采用

\[
(H,L,Z_{\mathrm{urgent}},E,K,M),
\]

其中 \(H\) 为迟到箱数，\(L\) 为总迟到秒数。正式输出必须满足 \(H=L=0\)。

## 4. 物理与资源口径

GIS、载荷、航程、飞行时间、能耗、SOC、充电和双资源排程口径保持不变：

- 所有无人机与满电电池在时刻0位于 O01；
- 每架次只携带一块兼容工作电池；
- 所有架次从 O01 出发并返回 O01；
- 换电和充电只在 O01 进行；
- 基准安全余量为20%；
- 基准航程—能量标定系数为 \(\alpha=1.0\)；
- 同一无人机的飞行占用区间不得重叠；
- 同一电池的飞行与充电占用区间不得重叠。

## 5. 公共模型改动

### 5.1 数据层

为物资箱提供：

- `is_urgent`：是否属于急送集合；
- `required_deadline_s`：本模型下必须满足的强制截止时间。

保留现有 `hard_deadline_s` 语义，避免破坏旧结果读取；新模型显式使用 `required_deadline_s`。

### 5.2 目标计算

新增急送优先目标计算函数，返回：

- 迟到箱数；
- 总迟到秒数；
- 急送物资加权归一化送达时间；
- 总能耗；
- 架次数；
- 完工时间。

旧目标函数保留，使用明确的目标模式选择新旧口径。

### 5.3 独立校验

新模式下，独立校验器检查全部80箱的 `required_deadline_s`。校验报告区分：

- 急送物资迟到；
- 普通物资迟到；
- 其他容量、能量、覆盖或资源错误。

## 6. 共同全按时种子

现有22/24架次结果各有1箱普通物资超过期望时间，不能直接作为新模型正式结果。种子构造流程调整为：

1. 生成基于服务区和容量的初始分组；
2. 执行完整物理评估与双资源排程；
3. 优先提取迟到箱并前移、拆分或换机型；
4. 急送物资迟到时优先独立成组或分配更快型号；
5. 普通物资迟到时只修复到按时，不奖励额外提前；
6. 全箱按时后再进行高能耗架次替换、合并和换型；
7. 输出 \(H=L=0\) 的共同可行种子。

若无法构造全箱按时种子，两个正式求解器不得继续输出“可行”状态，应返回“当前算法未找到全按时方案”。

## 7. 受限一体化 CP-SAT

CP-SAT 同时处理候选架次选择、起始时刻、实体无人机分配和实体电池分配。新模式下：

1. 所有物资箱的强制截止时间进入约束；
2. 共同全按时种子无条件进入候选池；
3. 种子的选择、开始时刻和资源分配作为 hint；
4. 按严格词典序分阶段求解：
   - 最小化 \(Z_{\mathrm{urgent}}\)；
   - 锁定急送目标后最小化 \(E\)；
   - 锁定能耗后最小化 \(K\)；
   - 最后最小化 \(M\)；
5. 每阶段使用数值容差锁定连续目标，避免浮点误差排除前阶段解。

CP-SAT 仍是受限候选池上的模型，不宣称覆盖原问题全部组合。

## 8. Hybrid 混合算法

Hybrid 由分组局部搜索、ALNS 邻域和候选架次重组构成。新模式下：

1. 从共同全按时种子启动；
2. 增加急送物资后移惩罚、普通物资迟到修复和急送物资换型操作；
3. 在 \(H=L=0\) 后，优先执行高能耗移除、架次合并和低能耗换型；
4. 所有候选按 \((H,L,Z_{\mathrm{urgent}},E,K,M)\) 比较；
5. 每次候选更新均重新执行完整物理评估和双资源排程；
6. 最终结果必须通过独立校验器。

## 9. 实验设计

只运行基准场景，不运行敏感性分析：

- 安全余量：20%；
- 能量标定系数：1.0；
- CP-SAT：运行1次；
- Hybrid：使用10个固定随机种子重复求解；
- 记录求解状态、运行时间、\(Z_{\mathrm{urgent}}\)、总能耗、架次数、完工时间和最低返航 SOC。

正式比较只包含 CP-SAT 与 Hybrid。旧的候选架次法和独立 ALNS 不进入新结果表。

## 10. 输出目录

新结果写入独立目录：

```text
outputs/problem_d_q2_urgent_priority/
```

目录包含：

- 两算法的架次、逐箱配送、无人机时间线、电池时间线和校验文件；
- `method_comparison.csv`；
- `hybrid_repetitions.csv`；
- Hybrid 收敛记录；
- 目标比较图；
- 资源甘特图；
- 路线图；
- 面向论文撰写者的模型、算法、求解流程和结果说明。

旧目录 `outputs/problem_d_q2_stage3/` 保留，不被新实验覆盖。

## 11. 测试与验收

### 11.1 单元测试

- 急送物资分类正确；
- 普通物资强制截止时间等于期望送达时间；
- 急送目标只统计31箱急送物资；
- 普通物资提前量不影响 \(Z_{\mathrm{urgent}}\)；
- 目标比较顺序为急送及时性、能耗、架次数、完工时间；
- 校验器能分别识别急送迟到和普通物资迟到。

### 11.2 集成测试

- CP-SAT 与 Hybrid 均只能将全箱按时方案标为可行；
- 80箱全部且仅送达一次；
- 质量、体积、航程、能量和 SOC 约束满足；
- 无人机与电池占用无重叠；
- 报告目标与独立复算一致；
- Hybrid 10个种子均产生明确状态，不把求解失败写成数学不可行。

### 11.3 完成条件

只有满足以下条件才更新论文指导文档：

1. 至少一个算法找到全箱按时可行解；
2. 所有正式可行解通过独立校验；
3. 两算法比较表与逐箱/逐架次明细一致；
4. 10次 Hybrid 重复实验完成；
5. 文档只介绍 CP-SAT 和 Hybrid，不再把旧四算法结果作为新模型结论。
