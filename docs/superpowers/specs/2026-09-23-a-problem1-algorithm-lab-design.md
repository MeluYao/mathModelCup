# A题问题一算法实验平台设计

## 1 目标与范围

本项目首先构建一个可复现的算法实验平台，用小规模、分层次的实验持续评估问题一切图与调度算法的理论假设。探索阶段不要求立即运行全部 100 个正式算例；先在合成图和代表性正式算例上淘汰性能不稳定、复杂度过高或机制解释不成立的候选，只对最终 2 至 3 个候选进行全部算例和 1 至 5 核验证。

问题一处于硬件场景 A。每个子图独立构成一个 Task，所有跨子图数据均经 DDR 中转。同核 Task 串行切换至少等待 100 cycles，跨核前驱完成后至少等待 1000 cycles。主目标为最小化 Makespan，次目标为减少额外数据搬运量。所有正式性能结论以附件中的问题一官方评估器为准。

本阶段交付可运行求解器、统一候选接口、实验驱动程序、合成测试图、代表性算例筛选结果和候选对比报告。不修改官方评估器，不把代理目标值当作最终成绩。

## 2 设计原则

### 2.1 正确性先于优化

任意候选必须满足以下条件：

- 每个非 `COPY_IN` 和 `COPY_OUT` 操作恰好属于一个子图；
- 子图收缩图为 DAG；
- 每个子图在 `core_schedules` 中恰好出现一次；
- 同核子图顺序不违反直接或间接依赖；
- 方案可由官方 `derive_multicore_plan` 接口验证；
- 官方问题一评估器能够完成仿真并生成结果。

候选在合成图或正式算例上出现非法方案时，该次结果记为失败，不用惩罚分数掩盖正确性问题。

### 2.2 机制可分离

将求解器拆为图画像、子图构造、分核排序、候选变换、代理筛选和官方评估六个模块。不同子图构造器可以复用同一个调度器，不同调度器也可以复用同一组子图，从而通过消融实验区分收益来源。

### 2.3 代理只负责节省评估预算

代理模型用于快速淘汰明显较差的候选。每一轮进入排名比较的候选必须经过官方评估器验证。代理模型需要分别保留关键路径、核心负载、DDR 下界、Task 等待、边界搬运和内存风险分量，不能只输出不可解释的总分。

### 2.4 探索和完全验证分离

探索阶段使用少量图、少量核数和逐步增加的搜索预算。候选冻结后再运行全部算例与全部核数。完全验证阶段不得根据测试结果继续修改被冻结算法或参数；如需修改，必须回到探索阶段重新筛选。

## 3 统一数据模型与接口

### 3.1 图画像

解析原始 Op-Tensor 二部图，排除原始 `COPY_IN` 和 `COPY_OUT` 后构造计算操作 DAG，同时保留 tensor 超边信息。图画像至少包含：

- 稳定拓扑序和关键路径优先拓扑序；
- 每个操作的 Pipe、cycles、直接前驱和后继；
- 每个 tensor 的位置、字节数、生产者和消费者；
- 上行秩、下行秩、拓扑层和近似并行宽度；
- Cube、Vector 与搬运相关工作量；
- tensor 扇出、候选边界搬运代价和近似生存区间；
- L1 与 UB 的近似活跃字节峰值。

画像计算必须在操作数和边数上保持近线性或低阶多项式复杂度，不能枚举全部子图组合。

### 3.2 子图方案

子图构造器统一输出：

- `blocks`：按子图 id 排列的操作 id 列表；
- `block_predecessors` 和 `block_successors`：收缩后的 DAG；
- `boundary_tensors`：每个有序子图对之间的 tensor 集合及字节数；
- `block_features`：Pipe 工作量、内部与边界字节、近似内存峰值和关键路径特征；
- `metadata`：算法名称、参数和可复现实验种子。

子图构造器必须自行保证操作覆盖、互斥和商图无环。统一验证器仍需在模块边界再次检查这些性质。

### 3.3 多核方案

调度器消费子图方案并输出每核有序子图列表。方案序列化时只写题目要求的 `node_to_subgraph` 和 `core_schedules` 两个字段，算法元数据单独写入实验记录，不污染提交文件。

## 4 候选算法族

### 4.1 C0 固定拓扑连续块基线

保留现有 `solver_minimal.py` 作为行为基线。它使用稳定拓扑序、固定工作量和操作数上限切块，再用简化最早完成时间规则分核。C0 不参与复杂调优，用于衡量新模块是否获得真实提升。

### 4.2 C1 多拓扑序动态规划切块

生成至少以下拓扑序：

- 操作 id 稳定优先；
- 下游关键路径优先；
- 大 tensor 通信优先；
- Pipe 交错与局部计算链优先。

对每个拓扑序构造允许的候选切点。分段代价由块计算不均衡、切割 tensor 字节、Task 数量、近似 L1/UB 峰值和丢失并行度组成。动态规划只在受限窗口或预筛选切点上转移，避免二次复杂度在最大图上失控。

C1 的理论优势是商图天然无环且可解释，主要检验“拓扑序质量和精细切点已足以获得稳定高质量方案”的假设。

### 4.3 C2 张量超图凝聚

初始簇为单操作或局部不可分计算链。候选合并收益定义为：

\[
G(A,B)=\Delta B_{\text{boundary}}
-\lambda_p\Delta P_{\text{parallel}}
-\lambda_m\Delta P_{\text{memory}}
-\lambda_w\Delta P_{\text{work}}
\]

其中边界收益按一个 tensor 的生产簇与不同消费簇集合计价，而不是逐条普通边重复计价。只有在合并后商图仍无环时才允许合并。候选合并使用优先队列，并在相邻簇变化后局部更新收益。

C2 主要检验“边界 tensor 和高扇出复用是问题一性能的主要决定因素”的假设。

### 4.4 C3 关键路径与 Fork-Join 分解

先计算关键路径和支配性的 Fork-Join 区域。关键路径上的紧密计算链优先保留在同一子图，互相独立的分支形成可并行子图，汇合点根据输入 tensor 大小和等待代价决定与关键路径或分支合并。

无法可靠识别结构的区域回退到 C1 的连续切块。C3 主要检验“显式结构并行度比通用通信聚类更能降低 Makespan”的假设。

### 4.5 公共内存风险模型

内存模型不单独形成首轮完整候选，而作为 C1、C2 和 C3 的公共代价项。模型按所选内部拓扑序估计 L1 和 UB tensor 的定义到最后使用区间，计算活跃字节峰值，并对接近容量或超过容量的候选块施加非线性惩罚。

该模型只用于相对排序。实际 spill 字节从官方评估结果读取，并用于校准模型，不以静态估计替代官方 Step2。

### 4.6 C5 受限局部搜索

C5 从 C1、C2 或 C3 的官方评估最优方案开始，支持以下邻域：

- 合并存在依赖或强通信关系的两个子图；
- 沿弱通信边界拆分子图；
- 将整个子图移动到另一核心；
- 交换同核上无依赖冲突的子图顺序；
- 将高扇出 tensor 的部分消费子图重新共置；
- 对关键路径附近的少量连续子图重新分核排序。

每个动作先经过增量合法性检查和代理筛选。每轮只对排名靠前的少量动作调用官方评估器，并缓存图、核数和方案哈希相同的结果。局部搜索受官方评估次数和墙钟时间双重预算限制。

## 5 分核与排序策略

### 5.1 S1 通信感知 HEFT

按子图上行秩或下游关键路径长度确定候选顺序。对每个核心计算预计最早开始时间和完成时间，至少计入：

- 当前核心可用时间；
- 同核前一个 Task 完成后的 100 cycles 切换等待；
- 跨核前驱完成后的 1000 cycles 等待；
- 边界 COPY 的 DDR 工作量；
- Cube 与 Vector Pipe 的块内工作量下界；
- 共享 DDR 拥塞的近似修正。

S1 是 C1 和 C2 的默认调度器。

### 5.2 S2 关键路径优先填充

先调度关键路径子图，随后把旁支子图填入不会延迟关键路径汇合点的核心空隙。S2 是 C3 的默认调度器，并与 S1 做消融比较。

### 5.3 S3 有限前瞻束搜索

在 S1 的贪心决策上增加 2 至 3 步前瞻。每层只保留固定宽度的部分调度状态，并以代理 Makespan 下界排序。S3 只在代表性图上用于检验前瞻收益；若收益不足以覆盖运行时间，不进入完全验证。

## 6 代理目标和理论下界

快速代理至少输出以下分量：

\[
\widehat T=\max\left(
T_{\text{critical}},
T_{\text{core-load}},
T_{\text{DDR}}
\right)
+P_{\text{task-wait}}
+P_{\text{spill}}
+P_{\text{imbalance}}.
\]

- `T_critical`：包含跨块等待和搬运估计的子图关键路径；
- `T_core-load`：每核 Pipe 工作量和 Task 切换的最大值；
- `T_DDR`：预计总 DDR 字节除以 60 B/cycle；
- `P_task-wait`：同核和跨核 Task 等待无法与其他工作隐藏的估计；
- `P_spill`：L1/UB 活跃峰值引起的非线性风险；
- `P_imbalance`：各核预计完成时刻离散程度。

这些值既用于筛选候选，也用于解释代理误差。每轮实验计算代理预测和官方 Makespan 的秩相关性；相关性持续偏低的分量需要重新校准或移除。

## 7 实验分层与淘汰流程

### 7.1 性质测试

为以下合成图建立确定性测试：

- 单链；
- 多条独立链；
- Fork-Join；
- 高扇出共享输入；
- Cube 与 Vector 交错；
- L1 临界容量；
- UB 临界容量；
- DDR 搬运主导。

测试既检查方案合法性，也检查方向性行为。例如高扇出图中 C2 不应比逐边计价产生更多无意义边界；独立链图在多核时应使用超过一个核心；单链图不得生成违反依赖的同核顺序。

### 7.2 代表性正式算例选择

对全部正式图只做只读画像，根据以下特征选择约 8 至 12 个代表性算例：

- 操作数和边数的大小极值与中位区域；
- DAG 深度和最大宽度；
- Cube、Vector 工作量比例；
- tensor 大小、扇出和边界通信潜力；
- L1、UB 近似内存压力；
- 关键路径下界与 DDR 下界的相对关系。

选择过程使用确定性规则，并保存算例名称与选择原因。探索阶段优先评估 2、4、5 核，只有候选进入决赛后再补齐 3 核和 1 核基准。

### 7.3 连续淘汰

候选按以下预算逐级晋级：

1. 所有候选通过合成性质测试；
2. 在 3 个结构差异明显的正式算例上进行首轮评估；
3. 删除被其他方案稳定支配、出现非法结果或求解时间不可接受的候选；
4. 剩余候选在 8 至 12 个代表性算例上评估；
5. 对前 2 至 3 个候选扩大参数和局部搜索预算；
6. 冻结算法与参数后运行全部正式算例和 1 至 5 核配置。

任何阶段都保留 C0 基线，防止所有复杂候选在某类图上共同退化。

### 7.4 排名与淘汰标准

先做 Pareto 支配判断，再按以下顺序比较：

1. 相对本轮最佳官方 Makespan 的标准化 regret；
2. 跨算例 Makespan 几何平均；
3. 最差算例退化幅度；
4. 额外搬运量和 spill 字节；
5. 求解时间、官方评估次数和结果稳定性。

不得为了平均值隐藏灾难性退化。若候选平均成绩较好但在某一图类持续明显退化，应保留为图类型专用策略或从通用候选中淘汰。

## 8 实验记录与可复现性

每次官方评估记录：

- 算例、核数、候选算法和完整参数；
- 输入图内容哈希和方案哈希；
- 求解时间和官方评估时间；
- Makespan、额外搬运量、分区搬运量和 spill 字节；
- 每核 Task 数、预计负载和官方时间线摘要；
- 代理目标各分量及与官方结果的误差；
- 成功、非法方案、超时或评估器错误状态。

实验结果采用机器可读 JSON Lines 保存，并生成汇总 CSV 与 Markdown 报告。相同图、核数、方案哈希和评估器配置的结果直接复用，避免重复运行官方仿真。

## 9 文件边界

计划新增以下职责清晰的文件：

- `A题/problem1/graph_model.py`：图解析、画像和公共数据结构；
- `A题/problem1/partitioners.py`：C1、C2 和 C3 子图构造器；
- `A题/problem1/schedulers.py`：S1、S2 和可选 S3 调度器；
- `A题/problem1/objectives.py`：代理目标、下界和增量估计；
- `A题/problem1/local_search.py`：C5 邻域和搜索预算；
- `A题/problem1/plan_io.py`：方案序列化、哈希和官方合法性验证；
- `A题/solver_problem1.py`：单算例命令行入口；
- `A题/experiment_problem1.py`：分阶段实验、缓存和报告入口；
- `A题/tests/`：合成图、性质测试和回归测试。

现有 `solver_minimal.py` 保留不动，作为 C0 基线和行为对照。官方附件代码只调用不修改。

## 10 错误处理与资源限制

- 图格式错误直接报告原始验证异常；
- 候选产生非法商图时记录构造器名称和导致失败的动作；
- 官方评估器失败时保留 stderr、退出码和最小复现命令；
- 每个候选支持确定性随机种子；
- 束搜索、局部搜索和官方评估都必须有显式次数与时间预算；
- 大图触发复杂度阈值时允许从 C2、C3 或 S3 回退到 C1 和 S1，但回退必须写入实验记录。

## 11 成功标准

探索平台完成的判据为：

- C0、C1、C2、C3 和 C5 可以通过统一接口运行；
- 所有性质测试和官方合法性验证通过；
- 能确定性选择代表性正式算例并执行连续淘汰；
- 对每个性能差异给出切图、调度、DDR、等待或 spill 层面的解释；
- 至少筛选出 2 个机制不同、值得完全验证的候选；
- 冻结候选后能够一条命令运行全部算例和全部核数，并生成可复核的汇总结果。
