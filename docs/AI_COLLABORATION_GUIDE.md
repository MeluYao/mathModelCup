# Codex / Claude Code 仓库操作规范

你是 `MeluYao/mathModelCup` 仓库的 AI 执行者。本文件只写给你，不用于教授成员 Git。成员只需要描述数学问题、数据含义、约束和期望结果；所有 Git 检查、分支维护、提交、推送和 Pull Request 准备均由你完成。

## 1. 开始前必须确认身份

本仓库只使用以下成员分支：

| 成员账号 | 固定工作分支 |
|---|---|
| `yf82289878` | `yf82289878` |
| `lyn18302` | `lyn18302` |

如果当前成员账号未知，先询问：“本次使用的账号是 `yf82289878` 还是 `lyn18302`？”

确认账号后：

- 只在对应的同名分支工作。
- 分支不存在时，从最新 `main` 创建同名分支。
- 分支已存在时，切换到该分支并同步最新 `main`。
- 不得按任务创建其他分支。
- 不得直接修改或提交到 `main`。
- 不得让成员手动输入 Git 命令。

## 2. 启动工作流程

每次开始任务时依次执行：

1. 阅读本文件、`README.md`、`.gitignore` 和 `environment.yml`。
2. 检查仓库根目录、当前分支、远程地址和工作区状态。
3. 如果存在来源不明的未提交修改，停止操作并向成员说明；不得覆盖、清理或暂存。
4. 获取远程更新，并用安全方式更新本地 `main`。
5. 创建或切换到成员的固定账号分支。
6. 将最新 `main` 同步到账号分支。若出现冲突，停止并按“冲突处理”章节执行。
7. 向成员报告当前分支、仓库状态和本次实施计划。

推荐状态报告格式：

```text
账号：<账号>
工作分支：<同名分支>
main 同步状态：<已同步/需要处理>
未提交修改：<无/文件列表>
计划修改：<文件与目的>
需要确认：<无/具体事项>
```

## 3. 提交注释必须使用中文

所有 commit 注释必须使用简体中文，准确说明变更目的。禁止使用纯英文注释，例如 `fix bug`、`update` 或 `docs`。

推荐格式：

- `新增：时间序列基线模型`
- `修复：缺失值处理导致的指标错误`
- `优化：减少特征计算的重复逻辑`
- `测试：补充边界条件验证`
- `文档：说明模型假设与运行方式`
- `配置：更新 Conda 环境依赖`

提交前先向成员展示建议的中文注释。只有成员确认后才能提交和推送。

## 4. 禁止上传的内容

以下内容仅保留在本地，不得加入 Git、提交或推送：

- `A题/`、`B题/`、`C题/`、`D题/`、`F题/`
- `评估报告/`
- 所有 `.docx` 赛题文档
- `tmp/`
- `data/raw/`、`data/processed/` 中的实际数据
- `outputs/` 中的图表、模型、报告及运行产物
- Conda 环境、虚拟环境、缓存和临时文件
- 密码、访问令牌、密钥、验证码及个人敏感信息

即使 `.gitignore` 已包含相关规则，提交前仍必须检查工作区与暂存区。发现误暂存时，只从暂存区移除，不得删除本地文件。

## 5. 数学建模项目约定

- 探索性分析和临时推导放在 `notebooks/`。
- 可复用、稳定的代码放在 `src/math_model_cup/`。
- 可执行入口放在 `scripts/`。
- 自动测试放在 `tests/`。
- 项目环境由 `environment.yml` 管理，目标版本为 Python 3.11。
- 原始数据、处理后数据和生成结果均不提交。
- 实现模型前先复述变量、单位、假设、约束、评价指标和成功标准。
- 优先建立可解释的简单基线，再增加复杂度。
- 稳定逻辑必须有测试；测试失败时不得通过删除或跳过测试来规避。

## 6. 实现、验证与提交

完成代码或文档修改后：

1. 运行与改动直接相关的测试。
2. 运行完整测试套件。
3. 检查 `git diff --check`。
4. 检查 `git status` 和暂存文件清单。
5. 明确确认禁止上传的文件均未出现。
6. 向成员报告变更摘要、测试结果、警告和建议的中文 commit 注释。
7. 等待成员明确确认。
8. 提交并推送当前账号分支。
9. 准备从账号分支到 `main` 的 Pull Request。
10. 报告分支名、提交号和 PR 链接，不得自行合并。

Pull Request 内容必须说明：

- 问题与目标
- 数学假设与约束
- 使用的方法
- 修改的文件
- 验证命令与结果
- 主要结论
- 已知限制和待审查问题

## 7. 必须先确认的操作

执行以下操作前，必须说明影响并获得成员明确确认：

- 提交或推送
- 创建或合并 Pull Request
- 删除、移动或重命名文件
- 放弃本地修改
- 解决会改变他人代码的冲突
- 发送协作者邀请或修改权限
- 公开仓库或对外发布内容
- 上传任何文件
- 修改依赖或重建环境
- 任何强制推送、历史改写或破坏性 Git 操作

禁止自行使用 `git reset --hard`、强制推送或删除未知来源的工作。

## 8. 冲突处理

发生合并冲突时：

1. 停止提交和推送。
2. 列出冲突文件。
3. 分别解释账号分支和 `main` 的修改意图。
4. 说明每种解决方式对数学逻辑、测试和其他成员工作的影响。
5. 提出逐文件解决建议。
6. 等待成员确认后再修改。
7. 解决后重新运行相关测试与完整测试。

不得盲目接受某一方、覆盖整个文件或使用破坏性重置。

## 9. 常见异常处理

### 误暂存赛题、数据或输出

只把这些文件从暂存区移除，不删除本地文件。检查 `.gitignore`，再次展示暂存清单，确认问题已消除。

### Conda 环境创建失败

读取完整错误，依次检查 Conda 版本、channel、网络和依赖冲突。先报告根因与最小修复方案。不得删除 `base` 或其他环境，也不得擅自更换 Python 版本。

### 测试失败

先稳定复现，再区分代码缺陷、环境问题和测试问题。提供错误证据与根因分析后再提出修复。不得删除、跳过或弱化测试以获得通过结果。

### 工作区存在未知修改

停止操作，列出文件和差异概况，询问成员这些修改的来源与处理方式。不得覆盖、暂存、提交或清理。
